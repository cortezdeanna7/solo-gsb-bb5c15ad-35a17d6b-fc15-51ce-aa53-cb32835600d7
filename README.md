# 家谱关系核对（本地网页应用）

一个**本地运行**的家谱关系核对工具：录入最多 **30 名**成员及其「父母 → 子女」关系
（每名子女至多两位父母），系统自动拒绝 **自指、重复边、祖先环路**；支持在成员选择器旁
维护一份**批量录入草稿**，一次预检即可看到每条草稿的错误与整批可否提交，合法批次原子写入。
成员区还提供**合并重复成员**入口：选择保留成员与被合并成员，预览时把被合并成员在全部关系中的
ID 替换为保留成员并去重，若产生自指、超过两位父母或祖先环路则列出冲突并禁止提交，提交带版本号、
服务端按同一规则重算后原子生效。
**任意一次成功写入（成员增删改、纪念日登记与清除、单条及批量关系变更、成员合并、备份恢复）都可一键撤销**：写入时把变更前的
完整家谱（成员 ID、姓名、纪念日与全部关系）作为唯一可撤销快照，与新状态、新版本在同一次落盘中原子持久化，
重启后仍可撤销；撤销本身推进版本并清空快照，因此只能撤销最近一次、不能重复撤销。
选中两人后，沿父母链找出**总代数最少的全部共同祖先**，并展示双方到各祖先的**全部最短亲缘路径与代数**
（同代数的不同路径全部保留）。没有共同祖先时会明确提示。支持随时修改关系后重新查询。
此外可一键进行**辈分矛盾核查**：枚举每一对存在祖先关系的成员，沿「父母 → 子女」关系分别求
**最少代数与最多代数**，两者不等（同一对祖先与后代沿不同路径辈分隔辈数不一致）才列为矛盾，
**同代不同路径不报警**；每条结果展示两端成员、代数差及最短、最长各一条完整成员链，支持按成员筛选，
接口只读，成员或关系变更后重新核查即可看到最新结果。
成员列表还提供**删除影响预览**入口：选中某位成员点击行内「删除影响」，服务端以当前家谱构造
**不落盘的只读假设图**移除该成员及其相连亲子关系，仅比较删除后仍在谱中的有序祖先→后代成员对，
列出**原本可达而删除后不可达**（删除后成员链为空）与**仍可达但最短代数增加**的成员对，
并给出变更前后各一条最短成员链；多路径按最短代数判定，**仍有同代替代路径的成员对不会误报为断联**。
预览标明所依据的家谱版本，家谱写入后旧结果标记过期，现有「删除」与「撤销」入口继续可用。
还有**变更影响预览**：选择「新增一条父母 → 子女关系」或「移除一条现有关系」，
系统以当前家谱构造**不落盘的假设图**试算——新增沿用成员存在、重复、父母上限与祖先环路校验，
失败会说明原因；通过时**逐对对比**变更前后的辈分矛盾，按祖先与后代成员对列出
**新增、消失与代数范围变化**的矛盾，并展示变化前后各自的最短与最长成员链（不是只比较矛盾总数）。
预览标明所依据的家谱版本，家谱发生写入后页面会提示重新预览。
另有**备份与恢复**入口：一键下载**仅含成员 ID、姓名、纪念日与父母→子女关系**的 JSON 备份，
便于把家谱迁移到另一台本地实例；选择备份文件后先**预览恢复**——服务端按 30 人上限、
每名子女至多两位父母、无自指/重复关系/祖先环路**逐条校验整份文件**，
重复 ID、缺失端点或非法关系逐项列出、绝不静默丢弃，预览显示将恢复的成员与关系数量及当前版本、
**不修改任何数据**；确认时携带预览返回的**内容指纹与版本**，服务端重新计算指纹并整份重验，
文件被调换或版本过期都拒绝，成功才**原子替换整个家谱**、版本加一并纳入最近一次撤销。
还有**成员纪念日**页：每名成员可登记**一个生日与一个忌日**（公历月日，不含年份，2 月 29 日合法），
可随时修改或清除；纪念日随成员数据一同持久化，删除成员、撤销与备份恢复时一并处理
（旧数据文件与旧备份缺少纪念日字段时视为未登记）。页面按**浏览器提交的本地日期**生成
**包含当天的未来 30 天**纪念日清单：逐年求每项纪念日的下一次发生日期，
**2 月 29 日在平年落到 2 月 28 日**，跨年同样准确；同一天的条目按**姓名、类型**（生日先于忌日）
稳定排序，并展示**距今天数**（今天 / 明天 / N 天后）。非法月日（如 2 月 30 日、13 月）
会被拒绝且不改变任何数据。
另有**后代支系视图**：任选一名现有成员作为**始祖**并设定 **1～10 代**上限，
沿「父母 → 子女」关系向下提取后代；同一后代经多条路径到达时**只显示一次**，
按距始祖的**最短代数**分组，并标记其所属的**每个始祖直系子女分支**
（在提取出的支系子图上判定可达性，不限于最短路径）；仅展示**两端都在支系内**的亲子关系，
不带入支系外成员。视图结果可下载为 JSON（含成员 ID、姓名、代数、所属分支与支系内关系），
文件内注明其为**局部导出而非整谱备份**；接口只读，成员或关系变更后重新生成即按最新状态计算。
另有**整谱关系图**入口：一键把当前全部成员与父母→子女关系绘成**可缩放的分层 SVG**——
先按**忽略方向**的关系划分连通分量（分量之间留白），各分量按**最长父母链**分层；
多位父母指向同一子女时**只绘一个成员节点**并保留各条连线；层内按直接父母节点横坐标
**重心**排序（平局按姓名、ID 稳定排序），没有父母的层按姓名、ID 排序，节点与姓名互不重叠。
图上标注**生成时的家谱版本**，可下载为 SVG 文件；整个模块**只读**，
家谱写入后页面会提示重新生成；空谱展示空状态。
另有**关键连接**入口：把当前全部成员与父母→子女关系视为**无向连接**，先按忽略方向的
连通分量（原本互不连通的家族）分组，再在各家族内部分别找出**桥梁关系**——
移除这一条关系就会把原来连通的家族拆成互不相连的两部分；逐条展示关系两端、所属家族，
以及断开后原家族**两侧的成员数与姓名**。两端之间仍有其他连接路径的关系
（如环形、钻石结构中任意一条边）**不会误报**。结果标注所依据的家谱版本，
家谱写入后页面提示重新计算；空谱与无桥梁时都有明确提示，整个模块**只读**。

技术栈：Node.js + Express + 原生 HTML/CSS/JavaScript（无前端构建步骤）。

## 一条命令启动

需要已安装 Docker 与 Docker Compose（v2）。在本项目目录执行：

```bash
docker compose up --build -d
```

启动后浏览器访问：

> **http://localhost:3000**

停止：

```bash
docker compose down
```

数据保存在 Docker 命名卷 `family-data` 中，停止或重建容器不会丢失；
如需彻底清空数据：`docker compose down -v`。

## 必要配置

全部配置均为**可选项**，默认值即可直接使用。

| 配置项 | 位置 | 默认值 | 说明 |
| --- | --- | --- | --- |
| 宿主机访问端口 | Compose 环境变量 `HOST_PORT` | `3000` | 端口被占用时可改，例如 `HOST_PORT=8080 docker compose up --build -d`，随后访问 http://localhost:8080 |
| 容器监听端口 | `docker-compose.yml` 中 `PORT` 与端口映射右侧 | `3000` | 一般无需修改；如需改动，两处需同时改 |
| 数据文件路径 | 环境变量 `DATA_FILE`（或 Compose 卷挂载） | `/app/data/family.json` | 家谱数据以 JSON 落盘，每次变更即时写入 |
| 监听地址 | 环境变量 `HOST`（仅裸 Node 运行时） | `0.0.0.0` | 容器内固定监听全部网卡 |

> 数据目录（`DATA_FILE` 所在目录，Compose 下为命名卷 `family-data`）必须**可写**。
> 每次变更都遵循「**先落盘、后发布**」：先在候选家谱上应用变更并完整写入磁盘
> （临时文件 + rename），成功后才更新内存；磁盘写满或权限不足导致写盘失败时，
> 接口返回 **500** 与可识别的 JSON 错误（`code: "PERSIST_FAILED"`），
> 内存中的成员、关系、纪念日、版本与最近操作快照全部保持原值，本次临时文件被清理，
> **不会出现「请求报错但 `/api/state` 已显示未落盘新数据」的漂移**；
> 恢复写盘条件（清理磁盘 / 修复权限）后重新提交即可。

> 该应用面向本地使用，不包含鉴权。请勿直接暴露到公网。

## 访问地址与端口

- 默认地址：**http://localhost:3000**
- 页面入口：浏览器直接打开 **http://localhost:3000**（无需账号，本地使用）；
  整谱关系图在页面「**⑨ 整谱关系图**」卡片、关键连接在页面「**⑩ 关键连接**」卡片
  （同一地址，无需单独端口）
- 健康/数据接口：`GET http://localhost:3000/api/state`
- 纪念日清单：`GET http://localhost:3000/api/anniversaries/upcoming?from=YYYY-MM-DD`
- 备份下载：`GET http://localhost:3000/api/backup`（仅含成员 ID、姓名、纪念日与关系的 JSON 附件）
- 后代支系视图：`GET http://localhost:3000/api/descendant-branches?root=<成员id>&maxGen=3`（只读，按最新家谱状态计算）
- 整谱关系图布局：`GET http://localhost:3000/api/family-chart`（只读，返回分层布局与生成时的家谱版本，前端据此绘制可缩放 SVG）
- 关键连接分析：`GET http://localhost:3000/api/critical-links`（只读，返回桥梁关系与断开后两侧成员名单，含所依据的家谱版本）

## 不使用 Docker（本地 Node 直接运行）

要求 Node.js ≥ 18。

```bash
npm ci          # 或 npm install
npm start
```

默认读取/写入 `./data/family.json`（自动创建），可用 `DATA_FILE` 与 `PORT` 覆盖：

```bash
PORT=8080 DATA_FILE=/path/to/family.json npm start
```

运行核心算法测试：

```bash
npm test
```

## 使用说明

0. **撤销最近一次变更**：页面顶部「**最近操作**」卡片显示最近一次成功写入的操作说明、发生时间与
   该操作所基于的家谱版本，右侧「**撤销**」按钮可一键回退：
   - 覆盖范围：成员的**添加 / 重命名 / 删除（含级联关系）**、**纪念日登记 / 修改 / 清除**、
     **单条关系建立 / 删除**、**批量关系提交**、**成员合并**与**备份恢复**——任何成功写入都会把
     **变更前的完整家谱**（成员 ID、姓名、纪念日、全部父母→子女关系）保存为**唯一**可撤销快照；
     后一次成功写入会覆盖前一次快照，故只能撤销**最近一次**操作。
   - 快照与新状态、新版本在**同一次 JSON 写盘**中原子持久化（临时文件 + rename），因此
     **重启容器 / 进程后仍然可以撤销**。
   - 所有写入（含撤销本身）都遵循「**先落盘、后发布**」：先在候选家谱（内存状态的深拷贝）上
     应用变更并完整写入磁盘，成功后才更新内存；写盘失败时成员、关系、纪念日、版本与
     最近操作快照全部保持原值，本次临时文件被清理，请求收到 **500** JSON 错误
     （`code: "PERSIST_FAILED"`），恢复写盘条件后可重试，且失败不产生新版本与新快照。
   - 点击撤销时请求携带页面当前所见的**家谱版本号**：若其他标签页（或脚本）在此期间已经修改家谱，
     服务端返回 **409 冲突且数据保持不变**，页面自动刷新为最新状态与最近操作。
   - 撤销成功后：成员 ID、姓名、纪念日与关系**整体恢复为变更前原貌**（合并撤销会让被合并成员带着原 ID 与
     姓名回来、被去重的关系也全部回来），家谱版本在原有基础上**继续 +1**、快照**清空并落盘**，
     因此**不能重复撤销**；直到下一次成功写入产生新快照。同时已有共同祖先查询结果会被标记为**过期**。
   - 被校验拒绝的操作（如自指、环路、冲突合并、版本不符的批量提交）**不产生快照**，
     撤销入口仍指向上一次真正成功的写入。
1. **添加成员**：在「① 成员」卡片逐个录入姓名，最多 30 人；可重命名、删除（删除会级联清除相关关系）。
   - **合并重复成员**：成员卡片下方的「合并重复成员」面板选择 **保留成员**（合并后保留其姓名）
     与 **被合并成员**（合并后删除），点击「**预览合并**」：
     - 预览把被合并成员在**全部父母 → 子女关系**中的 ID 替换为保留成员，展示**合并后的关系**、
       涉及被合并成员的关系数与**去重移除的重复关系数**；源自被合并成员的关系会标记「ID 已替换」。
       **预览不修改家谱**。
     - 替换后若产生以下任一情况，会逐项列出冲突并**禁止提交**（「确认合并」按钮保持禁用）：
       - **自指**：例如已有「张三 → 张叁」，再把「张叁」并入「张三」会得到「张三 → 张三」；
       - **子女超过两位父母**：去重后某子女仍有超过 2 位父母（针对绕过 API 的异常数据的防御性检查；
         经正常界面录入的数据合并后父母数只会减少，不会触发）；
       - **祖先环路**：合并使图中出现循环祖先关系（例如 `A→B→C`，把 A 并入 C 得到 `C→B→C`）。
     - 预览通过后点击「**确认合并**」：请求携带预览返回的**家谱版本号**，服务端按与预览**完全相同的规则重新计算**；
       若预览后家谱被任何操作改动（版本不符返回 **409**）或重算后仍有冲突（**400**），都**整单拒绝且不改任何数据**。
       成功时：保留保留成员的**原姓名**、关系按去重后的结果整体替换、删除被合并成员，
       **只落盘一次**且家谱版本加一，随后页面数据自动刷新并把已有共同祖先查询标记为过期。
     - **预览失效时机**：更换保留/被合并成员、或家谱被刷新/改动后，旧预览立即失效并要求重新预览。
   - **删除影响预览**：每位成员行内除「重命名」「删除」外还有「**删除影响**」按钮，
     删除前可先预览（**只读，不写家谱**）：
     - 服务端以当前家谱构造**不落盘的只读假设图**：移除该成员本身及与其相连的全部父母→子女关系
       （与真实删除的级联范围一致），仅比较删除后**仍在谱中**的有序祖先→后代成员对；
     - 以删除前（当前家谱）**原本可达**为准逐对枚举，在两张图上分别求**最短代数与一条最短成员链**，
       按最短代数判定并分两组列出：
       - **删除后不可达（断联）**：两人间全部通路都经过被删成员，删除后不再有祖先关系，
         变更后成员链为空（`after = null`）；
       - **最短代数增加（绕远）**：删除后仍可达但必须改走更长的替代路径，标注增加的代数
         （如最短 2 代 → 3 代）并给出变更前后各一条最短成员链；
     - **仍有同代替代路径的成员对不计入任何一组**（归入「不受影响」），因此不会把多路径情形
       误报为断联；端点之一就是被删成员的成员对随其离谱，不参与比较；
     - 顶部概要标明假设删除将移除的关系数、删除后剩余成员数、参与比较的成员对总数及三组计数，
       以及「**基于家谱版本 N** 的只读假设图试算」；家谱一旦发生任何写入（版本推进），
       旧结果上方出现**过期提示**需重新预览，被预览的成员若已被删除则结果自动收起。
     - 该预览不改变现有的「**删除**」按钮（级联删除并可撤销）与顶部「**撤销**」入口。
2. **建立关系**：在「② 父母 → 子女关系」中选择父母与子女，点击「建立关系」。
   以下操作会被服务端拒绝并弹出原因：
   - **自指**：选择同一人同时作为父母与子女；
   - **重复边**：同一条父母→子女关系已存在；
   - **超过两位父母**：每名子女最多登记两位父母；
   - **祖先环路**：例如已有 `A → B → C`，再添加 `C → A` 会使 C 成为自己的祖先。
3. **批量录入关系**：同一卡片中，在成员选择器旁可累计一份「父母 → 子女」**草稿**：
   - 选择父母与子女后点击「**加入批量草稿**」即可追加一条（可继续选择追加，草稿仅存在于浏览器）；
     每条草稿可单独「移除」，也可「清空草稿」（不影响已有关系）。
   - 点击「**预检整批**」：服务端把**当前已有关系与整批草稿合并**后统一校验，
     草稿区逐条显示 `✓ 合法` 或 `✗ N 项错误` 及具体原因；底部明确提示整批**可否提交**。
     校验覆盖：成员存在、自指、**批内重复与已有重复**、每名子女最多两位父母、**祖先环路**
     （含草稿内部成环、草稿与已有关系交叉成环）。**判定基于合并结果，与草稿顺序无关**，
     且任何一条无效整批都不可提交。
   - 预检通过后「**提交整批**」按钮才可点击。提交必须携带预检返回的**家谱版本号**；
     若预检之后家谱被任何操作（含其他标签页/脚本）改动，提交会被 **409 拒绝**并提示重新预检。
     合法批次在服务端**一次持久化**（只产生一个新版本），成功后自动清空草稿并刷新关系列表。
4. **核对共同祖先**：在「③ 共同祖先核对」选择成员甲、乙并查询：
   - 列出所有达到**最小总代数**（甲到祖先的代数 + 乙到祖先的代数）的共同祖先，可能有多位；
   - 分别展示甲、乙向上到每位祖先的**全部最短路径**；
   - 路径上标注代数（本人 0 代、父母 1 代、祖父母 2 代……），同代数但经过不同中间人的路径都会保留；
   - 其中一人本身就是另一人祖先时，该祖先本人一侧为 **0 代**；
   - 两人完全没有共同祖先时显示明确的「没有共同祖先」提示。
5. **修改后重新查询**：任意添加/删除关系、增删或重命名成员后，页面会提示上次结果可能过期，重新点击查询即可。
6. **核查辈分矛盾**：在「④ 辈分矛盾核查」可选择一位成员（可选）后点击「**核查辈分矛盾**」：
   - 系统枚举**每一对存在祖先关系的成员**（祖先、后代两人不同），以后代为起点沿父母链向上，
     分别求到该祖先的**最少代数**（BFS 首达步数）与**最多代数**（DAG 上的最长路）；
   - **仅当最少代数 < 最多代数时列为矛盾**。例如后代到同一祖先既有一条 2 代短链、又有一条 3 代长链，
     则报告「最短 2 代 / 最长 3 代 / 代数差 1 代」；
   - **同代不同路径不报警**：例如同时经父系、母系以相同的 2 代到达同一祖父母（钻石结构），最少与最多代数相等，不计为矛盾；
   - 每条矛盾展示**两端成员**（祖先与后代）、**代数差**以及**最短、最长各一条完整成员链**
     （链按「祖先 → 子女 → … → 后代」自上而下展示，链上标注代数），结果按代数差从大到小排列；
   - **按成员筛选**：选择一位成员后只列出其作为祖先或后代端点参与的矛盾；未参与矛盾时给出明确提示，
     并告知全家家谱的矛盾总数（清空筛选可查看全部）；
   - 核查为**只读查询**，不产生写入、不改变家谱版本、不产生撤销快照；
     成员或关系变更（含合并、撤销）后，旧结果会被标记为**过期**，重新点击核查即得到最新结果。
7. **变更影响预览**：在「⑤ 变更影响预览」选择**变更类型**（新增一条父母 → 子女关系 /
   移除一条现有关系）与**父母、子女**两位成员，点击「**预览影响**」：
   - 系统以当前家谱构造**不落盘的假设图**试算该变更，**不写家谱、不改变版本、不产生撤销快照**；
   - **新增**沿用与真实建边完全相同的校验（成员存在、自指、重复边、每名子女至多两位父母、
     祖先环路），校验失败会弹出具体原因且不产生对比；**移除**的目标关系不存在时同样说明原因；
   - 校验通过时，在变更前与假设图上分别核查辈分矛盾，**按祖先与后代成员对逐对对比**
     （不是只比较矛盾总数），分三组列出：
     - **新增的矛盾**：变更后新出现的矛盾对，展示变更前状态（本无祖先关系，或辈分一致及其成员链）
       与变更后的最短、最长成员链；
     - **消失的矛盾**：变更后不再是矛盾的对，展示变更前双链与变更后状态；
     - **代数范围变化的矛盾**：前后都是矛盾但 `[最少代数, 最多代数]` 范围发生变化的对，
       两侧的最短、最长成员链都完整展示——例如新增一条短链后矛盾总数不变，但某对的范围从
       2/4 代变为 1/4 代，只有逐对对比才能发现；
   - 顶部概要标明「**基于家谱版本 N** 的假设图试算」及前后矛盾总数与三组数量；
     家谱一旦发生任何写入（或预览条件被修改），结果上方会出现**过期提示**，需重新点击预览。
8. **备份与恢复**：在「⑥ 备份与恢复」卡片操作，用于把当前成员与父母→子女关系迁移到另一台本地实例：
   - **下载备份**：点击「下载备份（JSON）」得到仅含**成员 ID、姓名与关系**的 JSON 文件
     （格式见下文「备份文件格式」，不含版本号与撤销快照）；
   - **预览恢复**：选择备份文件后点击「预览恢复」，服务端对**整份文件**逐条校验——
     30 人上限、成员 id/姓名合法且**无重复 ID**、关系端点都存在、无自指、无重复关系、
     每名子女至多两位父母、无祖先环路；发现的问题**逐项列出**（重复 ID、缺失端点、
     非法关系各自定位到第几项），**绝不静默丢弃**任何条目。预览显示将恢复的
     **成员与关系数量、成员名单及当前家谱版本**，且**不修改任何数据**；
   - **确认恢复**：仅在校验通过后可点击。请求携带预览返回的**内容指纹（SHA-256）与家谱版本**，
     服务端重新计算指纹并**整份重验**：文件在预览后被调换（指纹不符）或家谱已被修改（版本过期）
     都返回 **409** 且零写入，需重新预览；重验发现非法返回 **400** 并附逐项错误。
     成功时**原子替换整个家谱**（成员 ID 原样保留）、版本 +1、一次落盘，
     并纳入**最近一次撤销**——恢复前家谱成为唯一可撤销快照，误恢复可一键回退；
   - 预览在以下情况失效需重新预览：重新选择文件、家谱发生任何写入。
9. **成员纪念日**：在「⑦ 成员纪念日」卡片为每名成员登记**一个生日与一个忌日**（公历月日）：
   - 点击成员行的「**登记** / **修改**」展开行内编辑：生日、忌日各选「月」并填「日」，
     月选「**不登记**」即清除该项；「**清除**」一键置空两项。保存即随成员数据落盘，
     删除成员时纪念日一并删除，撤销与备份恢复时也随之处理；
   - **2 月 29 日可以登记**（如闰年生日）；非法月日（2 月 30 日、4 月 31 日、13 月等）
     会被服务端拒绝且**不改变任何数据**；
   - 卡片顶部展示**未来 30 天纪念日**清单：按本机今天（浏览器本地日期）生成、**包含当天**，
     每项纪念日在窗口内只出现一次（下一次发生日期）；**2 月 29 日在平年按 2 月 28 日提醒**
     （清单中会标注「登记 2月29日（平年按 2月28日）」），跨年（如 12 月查看 1 月的纪念日）同样准确；
   - 清单按距今天数升序，同一天按**姓名、类型**（生日先于忌日）稳定排序，
     每项展示发生日期、星期、成员、类型与**距今天数**（今天 / 明天 / 后天 / N 天后）；
   - 清单为只读查询，任何纪念日或成员变更后自动刷新。
10. **后代支系视图**：在「⑧ 后代支系视图」选择一名现有成员作为**始祖**与 **1～10 代**的代数上限，
    点击「**生成支系视图**」（只读查询，不修改家谱、不改变版本）：
    - 沿「父母 → 子女」关系向下提取后代：同一后代经多条路径到达时**只显示一次**，
      按距始祖的**最短代数**分组展示（第 0 代为始祖本人）；
    - 每名成员标记其所属的**全部始祖直系子女分支**（如「张甲系」「张乙系」）：
      只要在提取出的支系子图中某位直系子女沿关系向下可到达该成员（不限于最短路径），
      该成员即归属对应分支，因此一名后代可同时属于多个分支；
    - **仅展示两端都在支系内**的亲子关系：支系外成员（如未录入为后代的配偶）及其关系
      一律不带入，超出代数上限的世代与其关系也不展示；
    - 点击「**下载当前结果（JSON）**」导出当前视图：含成员 ID、姓名、代数、所属分支与
      支系内关系，文件内 `note` 字段明确注明这是**局部导出而非整谱备份**
      （整谱备份请用「⑥ 备份与恢复」）；结果过期（家谱已变更或查询条件被修改）时
      按钮禁用，需重新生成后再下载；
    - 成员或关系发生任何变更后，旧结果上方会出现**过期提示**，重新点击生成即按最新状态计算。
11. **整谱关系图**：在「⑨ 整谱关系图」点击「**生成整谱关系图**」（只读查询，不修改家谱、不改变版本）：
    - 把当前**全部成员**与父母→子女关系绘成一张分层 SVG：先按**忽略方向**的关系划分
      **连通分量**（没有任何关系的成员各自成为单成员分量），分量之间留白、各自水平居中；
      每个分量按**最长父母链**分层——没有父母的成员在第 0 层，其余成员的层号为其直接父母
      最大层号 + 1；
    - **多位父母指向同一子女时只绘一个成员节点**，每条父母→子女关系各保留一条带箭头的连线
      （父母在上、子女在下）；层内按直接父母节点横坐标的**重心**排序，平局按姓名、ID 稳定排序，
      没有父母的层按姓名、ID 排序；节点宽度按姓名估计并保留最小间距，**节点与姓名互不重叠**；
    - 图上标注**生成时的家谱版本**（成员数、关系数、连通分量数一并展示）；
      可**拖动平移**、**滚轮或按钮缩放**、「适应窗口」一键复位；
    - 点击「**下载当前图（SVG）**」导出自包含的矢量图文件（白色背景、带版本标注，
      文件名含家谱版本，如 `family-chart-v8-2026-09-26.svg`）；
    - 整个模块**只读**：不产生写入、不改变版本、不产生撤销快照；家谱发生任何写入后，
      旧图上方会出现**过期提示**且下载按钮禁用，重新生成即按最新状态计算；
    - **空谱**（没有任何成员）时展示空状态提示，不绘图。
12. **关键连接**：在「⑩ 关键连接」点击「**查找关键连接**」（只读查询，不修改家谱、不改变版本）：
    - 把当前全部成员与父母→子女关系视为**无向连接**，先按忽略方向划分连通分量
      （原本互不连通的家族），再在各家族内部**分别**找出**桥梁关系**——
      移除这一条关系就会把该家族拆成互不相连的两部分；
    - 逐条展示关系两端（父母 → 子女）、所属家族，以及断开后原家族**两侧的成员数与姓名**
      （父母一侧与子女一侧分别列出）；多于一个家族时概要中给出各家族的成员数与关键连接数；
    - 两端之间仍有其他连接路径的关系**不会**被列为关键连接（例如环形、钻石结构中
      任意一条边，移除后成员仍可经其他路径连通），不会误报；
    - 结果标注**所依据的家谱版本**；家谱发生任何写入后，旧结果上方会出现**过期提示**，
      重新点击查找即按最新状态计算；
    - **空谱**（没有任何成员）与**无桥梁**（没有任何关键连接）时都会给出明确提示。

## HTTP API（便于自行核对 / 脚本调用）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/state` | 获取全部成员与关系（含单调递增的 `version` 家谱版本号，及最近一次可撤销操作 `undo`：`{ label, time, version }`，无快照时为 `null`） |
| `POST` | `/api/members` | `{ "name": "张三" }` 新增成员（上限 30） |
| `PATCH` | `/api/members/:id` | `{ "name": "新姓名" }` 重命名 |
| `PUT` | `/api/members/:id/anniversaries` | `{ "birthday": { "month": 3, "day": 15 } \| null, "deathday": { "month": 10, "day": 2 } \| null }` 登记/修改/清除纪念日：两字段必须同时给出（不登记显式传 `null`）；非法月日（如 2 月 30 日）返回 **400** 且数据不变；成员不存在返回 **404**；成功写入随成员落盘并可撤销 |
| `GET` | `/api/anniversaries/upcoming?from=YYYY-MM-DD` | **只读**未来 30 天纪念日清单：按提交的本地日期生成、包含当天；逐项给出下一次发生日期（2 月 29 日平年落到 2 月 28 日、跨年准确）、`daysUntil` 距今天数（当天为 0），按距今天数升序、同日按姓名与类型（生日先于忌日）稳定排序；`from` 省略时取服务器本地当天，格式非法返回 **400** |
| `DELETE` | `/api/members/:id` | 删除成员并级联删除相关关系（纪念日随成员一并删除） |
| `POST` | `/api/members/delete-impact/preview` | **只读**删除成员影响预览：`{ "memberId": "..." }`，以当前家谱构造不落盘的只读假设图（移除该成员及其相连亲子关系），仅比较删除后仍在谱中的有序祖先→后代成员对，按最短代数返回 `disconnected`（原本可达、删除后不可达，`after` 为 `null`）与 `lengthened`（仍可达但最短代数增加，含 `genIncrease`）两组明细（每条附变更前后各一条最短成员链 `before/after.shortestPath`），多路径同代替代不计断联；另返回 `removedEdgeCount`、`remainingMemberCount`、`comparedCount`、两组计数、`unaffectedCount` 与当前 `version`（不写入）；缺少 `memberId` 或成员不存在返回 **400** |
| `POST` | `/api/edges` | `{ "parentId": "...", "childId": "..." }` 建立父母→子女关系（含全部合法性校验） |
| `DELETE` | `/api/edges` | 同上请求体，删除关系 |
| `POST` | `/api/undo` | `{ "version": <当前所见版本> }` 撤销最近一次成功写入：恢复变更前完整家谱（成员 ID/姓名/关系原貌），版本继续 +1 且清空快照；版本不符（其他标签页已修改）或无快照时返回 **409**（带 `currentVersion`）且数据不变；缺少版本号返回 **400**；成功返回最新 state 与 `undone`（被撤销操作的说明） |
| `POST` | `/api/edges/batch/preview` | `{ "edges": [...] }` 批量预检：在「当前关系+整批草稿」合并结果上校验，返回每条草稿的 `errors`、整批 `valid` 与当前 `version`（不写入） |
| `POST` | `/api/edges/batch` | `{ "version": <预检返回的版本>, "edges": [...] }` 批量提交：版本不符返回 **409** 并带 `currentVersion`；任一条非法返回 **400** 且零写入；全部合法时原子写入并返回最新 state |
| `POST` | `/api/members/merge/preview` | `{ "keepId": "...", "mergeId": "..." }` 合并预检：把被合并成员在全部关系中的 ID 替换为保留成员后去重，返回合并后的 `edges`（含 `replaced` 标记）、`removedDuplicateCount`、`affectedEdgeCount`、`conflicts` 与当前 `version`（不写入） |
| `POST` | `/api/members/merge` | `{ "version": <预览返回的版本>, "keepId": "...", "mergeId": "..." }` 合并提交：版本不符 **409**（带 `currentVersion`）、仍有冲突 **400**（带 `preview` 冲突明细）均整单拒绝零写入；成功时保留保留成员姓名、去重关系、删除被合并成员，一次落盘版本加一，返回最新 state |
| `GET` | `/api/common-ancestors?personA=<id>&personB=<id>` | 查询最少总代数的全部共同祖先及全部最短路径 |
| `GET` | `/api/generation-conflicts?member=<id>` | **只读**辈分矛盾核查：枚举全部祖先—后代对，返回最少/最多代数不一致的矛盾（各含一条最短与最长完整成员链）；`member` 可选，给出时只返回该成员作为祖先或后代端点参与的矛盾（`total` 仍为过滤前总数）；成员不存在返回 **404** |
| `GET` | `/api/descendant-branches?root=<id>&maxGen=<1-10>` | **只读**后代支系视图：以 `root` 为始祖提取 `maxGen` 代以内后代，同一后代只出现一次、按最短代数分组并标记所属的全部始祖直系子女分支，仅含两端都在支系内的关系；返回 `version`、`branches`、`members`（各含 `gen` 与 `branches`）与 `edges`；缺少 `root` 或 `maxGen` 非 1～10 整数返回 **400**，始祖不存在返回 **404** |
| `GET` | `/api/family-chart` | **只读**整谱关系图布局：把全部成员与父母→子女关系排布成分层平面图（忽略方向划分连通分量、各分量按最长父母链分层、层内按直接父母横坐标重心→姓名→ID 排序），返回 `version`（生成时的家谱版本）、`caption`（图上的版本标注）、画布 `width`/`height`、分量背景带 `components`、节点 `nodes`（含坐标、宽高、层号与所属分量）与连线 `edges`（含两端姓名）；空谱返回 `empty: true` |
| `GET` | `/api/critical-links` | **只读**关键连接（桥梁关系）分析：把全部成员与父母→子女关系视为无向连接，按连通分量（原本互不连通的家族）分别找出「移除单条就会拆开其家族」的关系；每条含两端成员姓名、所属家族及断开后两侧（父母一侧 / 子女一侧）各自的成员数与姓名名单；返回 `version`（所依据的家谱版本）、`componentCount`、`bridgeCount`、`components`（各家族成员数与桥梁数）与 `bridges`；空谱返回 `empty: true` |
| `POST` | `/api/edges/impact/preview` | **只读**变更影响预览：`{ "action": "add" \| "remove", "parentId": "...", "childId": "..." }`，以当前家谱构造不落盘的假设图，逐对对比变更前后的辈分矛盾，返回 `added` / `removed` / `changed` 三组明细（每条含变更前后两侧的 `minGen`/`maxGen` 与最短、最长成员链）及 `beforeTotal`/`afterTotal`/`unchangedCount` 与当前 `version`；新增校验失败或移除目标不存在返回 **400** 并说明原因 |
| `GET` | `/api/backup` | 下载备份：仅含成员 ID、姓名、纪念日与父母→子女关系的 JSON 附件（格式见「备份文件格式」） |
| `POST` | `/api/backup/restore/preview` | **只读**恢复预览：`{ "content": "<备份文件原文>" }`，整份严格校验（30 人上限、重复 ID、缺失端点、自指、重复关系、每名子女至多两位父母、祖先环路），返回 `valid`、逐项 `errors`、`memberCount`/`edgeCount`/`memberNames`、内容指纹 `fingerprint` 与当前 `version`（不写入任何数据） |
| `POST` | `/api/backup/restore` | 备份恢复确认：`{ "version": <预览返回的版本>, "fingerprint": "<预览返回的指纹>", "content": "<备份文件原文>" }`；版本过期或指纹不符（文件被调换）返回 **409**（带 `currentVersion`），重验失败返回 **400**（带逐项 `errors`），均零写入；成功时原子替换整个家谱、版本 +1 并纳入最近一次撤销，返回最新 state |

校验失败统一返回 HTTP 400/404/409 与 `{ "error": "原因" }`。
写盘失败（如数据目录不可写、磁盘写满）统一返回 HTTP 500 与
`{ "error": "原因", "code": "PERSIST_FAILED" }`，本次变更完全不生效（内存与磁盘均保持原值），
恢复写盘条件后可重新提交。
合并冲突时 400 响应会附带与预检结构相同的 `preview`（含 `conflicts[].message` 可读冲突说明）。

## 备份文件格式

`GET /api/backup` 下载的备份为**仅含成员 ID、姓名、纪念日与关系**的 JSON 文件
（不含家谱版本号与撤销快照，可直接迁移到另一台本地实例恢复）：

```json
{
  "members": [
    { "id": "9b1d6f2e-…", "name": "张三", "birthday": { "month": 3, "day": 15 }, "deathday": null },
    { "id": "7c2e4a81-…", "name": "张小三", "birthday": null, "deathday": null }
  ],
  "edges": [
    { "parentId": "9b1d6f2e-…", "childId": "7c2e4a81-…" }
  ]
}
```

- `members`：每项含 `id`（非空字符串，全局唯一）与 `name`（非空、至多 50 字）；最多 30 人；
  `birthday` / `deathday` 为公历月日 `{ "month": 1-12, "day": 1-31 }`（2 月允许 29 日）或
  `null`（未登记）；**旧备份缺少这两个字段时视为未登记**，字段存在但非法（如 2 月 30 日）
  会逐项报错并整单拒绝；
- `edges`：每项含 `parentId` 与 `childId`（父母 → 子女），两端必须出现在 `members` 中；
  不允许自指、重复关系，每名子女至多两位父母，整体不得形成祖先环路；
- 恢复时服务端对**整份文件**逐条校验并一次性返回全部问题（`errors[].where` 为
  `file` / `member` / `edge`，`index` 为 0 起始的条目下标，`message` 含 1 起始的可读定位），
  任何一项不合法都整单拒绝、不静默丢弃；
- 恢复确认必须携带预览返回的 `fingerprint`（内容 SHA-256）与 `version`：
  文件被调换或家谱版本过期都会被 **409** 拒绝；成功后家谱整体替换、版本 +1，可经撤销回退。

```
    ├── criticalLinks.test.js # 关键连接：链/环/钻石结构桥判定、有其他路径不误报、多家族分别计算、两侧名单排序、HTTP 只读
    ├── undo.test.js        # 撤销：覆盖各类写入、重启持久化、一级快照、版本冲突 409
    ├── persistFailure.test.js # 写盘失败防护：先落盘后发布、内存/磁盘不漂移、临时文件清理、可识别 500 JSON 错误、恢复后可重试（含 HTTP 端到端）
    └── store.test.js       # 持久化、家谱版本与批量/合并的原子提交/409 测试
```

## 算法说明

- 图模型为有向图 `父母 → 子女`，查询时沿 `父母` 方向向上遍历；数据结构保证其为 DAG。
- 共同祖先：对两人分别做 BFS，记录到每个祖先的最短代数以及该代数下的**所有路径**
  （BFS 首次到达即最短；同一最短代数经不同前驱再次到达时把新路径合并保留）。
- 取两人祖先集合的交集，按 `代数A + 代数B` 取最小值，输出达到该最小值的全部祖先。
- 辈分矛盾核查：以每位成员为「后代」沿父母链向上做 BFS，得到其全部祖先的**最少代数**与一条最短链；
  再在该可达祖先子图（DAG）上做记忆化 DFS 求**最多代数**——向上走的边为「子女 → 父母」，
  故 `最长(祖先 v) = max(最长(v 的某可达子女 c)) + 1`，后代本人为 0——并沿最优前驱重建一条最长链。
  仅当同一对祖先/后代的 `最多代数 > 最少代数` 时报告矛盾，因此**同代不同路径（两者相等）不会报警**；
  每一对祖先/后代只枚举一次，结果按代数差、最多代数排序。该接口为纯只读，直接基于当前内存家谱计算，
  不产生写入与版本变化，因此成员或关系变更后重新查询即得到最新结果。
- 变更影响预览：纯函数构造**假设图**——深拷贝父母邻接表后应用一条「新增 / 移除」变更，
  当前家谱与数据文件完全不动。新增先复用与真实建边相同的 `validateEdge` 校验
  （成员存在、自指、重复、父母上限、祖先环路），失败直接返回原因；
  随后在「当前图」与「假设图」上分别跑同一套辈分矛盾核查，按 `祖先|后代` 成员对逐对对比：
  仅一侧存在的列为**新增 / 消失**，两侧都在但 `[minGen, maxGen]` 不同的列为**代数范围变化**
  （每条都附两侧的代际档案与最短、最长成员链，某侧无祖先关系时为 `null`），
  范围完全一致的计入 `unchangedCount`——因此结果不是只比较矛盾总数。
  响应携带当前家谱 `version`，前端据此标注「基于版本 N」并在任何写入后提示重新预览。
- 删除成员影响预览：纯函数构造**只读假设图**——从成员表移除目标成员，并在深拷贝的父母邻接表上
  丢弃以其为父母或子女的全部边，当前家谱与数据文件完全不动；删除后剩余成员上跑同一套
  祖先档案（BFS 求最短代数与一条最短链）。比较范围限定为删除后仍在谱的两人不同的有序
  祖先→后代成员对，以**删除前当前家谱原本可达**为准逐对枚举（端点之一是被删成员的对随其离谱、
  不参与比较）：变更后档案缺失为**断联**（`after = null`），变更后最短代数严格变大为
  **代数增加**（附 `genIncrease` 与两侧最短链），最短代数不变（含仍有同代替代路径的多路径情形）
  计入 `unaffectedCount`——删边删点只会消除路径，不会出现更短或新可达的对，
  因此按最短代数判定即可避免把仍有替代路径的成员对误报为断联。响应携带当前家谱 `version`，
  前端标注「基于版本 N」，任何写入后旧结果标记过期；该预览只读，不影响现有删除与撤销入口。
- 后代支系视图：自始祖沿「父母 → 子女」向下做限深 BFS（1～10 层），首达步数即**最短代数**，
  同一后代只保留一次；再以提取出的成员集为支系子图，从每位直系子女（第 1 代）分别向下
  DFS 求可达集，得到每名成员所属的**全部分支**（不限于最短路径，故一名后代可同属多支）；
  关系列表只保留父母与子女都在子图内的边，支系外成员一律不带入。接口纯只读，
  直接基于当前内存家谱计算并携带版本号，成员或关系变更后重新查询即得最新结果；
  下载的 JSON 由页面按当前展示结果生成，文件内注明其为局部导出而非整谱备份。
- 整谱关系图：先按**忽略方向**的关系用并查集把成员划分成连通分量（无关系的成员各自成量），
  分量按「姓名、ID 最小成员」稳定排序后自上而下堆叠、之间留白并水平居中。
  每个分量内部用记忆化 DFS 求各成员的**最长父母链层号**（无父母为第 0 层，
  否则为直接父母最大层号 + 1；家谱是 DAG，必然收敛）。层内排序：第 0 层按姓名、ID；
  其余层自上而下处理，按直接父母节点横坐标的**重心**（平均值）升序，平局按姓名、ID——
  处理到某层时其父母所在层坐标已确定。节点宽度按姓名估计（全角/半角字符分别计宽），
  同层从左到右依次排开并保留最小间距，各层在分量宽度内水平居中，因此节点与姓名互不重叠；
  同一成员只布局一个节点，每条父母→子女关系各保留一条连线（父母必在子女上方）。
  接口纯只读，直接基于当前内存家谱计算并携带版本号，图上的版本标注文本随布局一并生成
  （画布宽度已为标注预留），家谱写入后页面提示重新生成。
- 关键连接（桥梁关系）：把父母→子女关系视为**无向边**（每对成员之间至多一条关系，
  反向即祖先环路、录入时已被拦截，故无向化后无平行边）。从各成员出发做迭代式 DFS，
  一次遍历同时完成**连通分量（家族）划分**与 **Tarjan 桥查找**：维护发现时间 disc 与
  可回溯到的最早发现时间 low，树边 (u→v) 满足 `low[v] > disc[u]` 即为桥——
  v 的子树无法绕过这条边回到 u 及其祖先。原本互不连通的家族各自独立判定；
  因为判定基于全图连通性，两端仍有其他路径的关系（环形、钻石结构中的边）
  天然**不会被误报**。对每条桥，移除它后从父母端 BFS 得到「父母一侧」成员集合，
  分量内其余成员即「子女一侧」，两侧名单按姓名、ID 稳定排序。接口纯只读，
  直接基于当前内存家谱计算并携带版本号，家谱写入后页面提示重新计算。
- 批量预检：先对草稿做结构校验（成员存在、自指）并按 `子女+父母` 对找批内重复；
  再以「已有关系 ∪ 批内去重新边」构造合并图，在合并图上统一判定**重复、父母上限与环路**。
  因为所有结论都取自最终合并图而非逐条累加，**草稿的排列顺序不改变任何判定**；
  一条边被标记环路，当且仅当在合并图中其父母沿父母链可到达其子女。
- 并发控制：每次成功变更都让 `version` 加一并随数据落盘；批量提交是
  「比对版本 → 重跑与预检完全相同的校验 → 一次写入一次落盘」的原子过程，
  版本不符（409）或任一条非法（400）时不写入任何一条。
  所有写入都「先落盘、后发布」：先在候选家谱（内存状态的深拷贝）上应用变更，
  完整落盘成功后才发布到内存；临时文件写入或重命名失败时本次变更完全不生效
  （内存中的家谱、版本与撤销快照保持原值，与磁盘一致），本次临时文件被清理，
  接口返回 **500** 与 `code: "PERSIST_FAILED"` 的 JSON 错误，恢复写盘条件后可重试。
- 合并成员：预检是纯函数——把被合并成员在全部边端点上的 ID 映射为保留成员，
  映射后自指的边单独列为 `self` 冲突且不进入合并图，其余按「子女+父母」去重并统计去重数；
  再在合并图上检查每名子女父母是否超过 2 位，并对每条边用与建边相同的可达性判定标记环路。
  提交复用「比对版本 → 按同一规则重算 → 重建关系表并删除被合并成员 → 一次落盘」的原子过程，
  保留成员的姓名不被修改；版本不符或存在冲突时整单拒绝、数据保持不变。
- 撤销：所有成功写入都走同一个提交入口——先抓取变更前完整家谱
  （`{ maxMembers, members, edges }` 的深拷贝）作为唯一撤销快照，
  再在候选家谱（当前内存状态的深拷贝）上应用变更、版本 +1，
  把 `{ 候选家谱, version, undo: { label, time, version, family } }` 写入同一个 JSON 文件
  （临时文件 + rename，崩溃也不会出现「新状态与快照分属两次写盘」），
  **完整落盘成功后才把候选家谱、新版本与快照发布到内存**；落盘失败时内存保持原值、
  本次临时文件被清理，接口返回可识别的 500 JSON 错误（`code: "PERSIST_FAILED"`），
  恢复写盘条件后可再次提交。
  `/api/state` 只返回快照元数据（操作说明、时间、基线版本）而不返回家谱副本；
  撤销时先做与批量/合并相同的版本比对（不符 **409** 且零改动），再以快照重建候选家谱、
  版本继续 +1、快照置为 `null`，同样先落盘成功后才发布到内存，
  故**重启后可撤销、只能撤销一次、不能重复撤销**，撤销写盘失败时快照保留、可重试。
  撤销恢复的是序列化的完整家谱，成员 ID、姓名与关系原貌一一还原；合并被撤销后，
  被合并成员的原 ID/原姓名及被去重的边都会回来。前端在撤销成功后同样把共同祖先查询标记为过期。
- 备份与恢复：下载接口把当前家谱序列化为仅含成员 ID、姓名、纪念日与边表的 JSON。
  恢复预览把文件原文解析后**整份严格校验**——成员结构（id/姓名非空、姓名 ≤ 50 字）、
  30 人上限、重复 ID（每个副本逐项报错并指出与第几项重复）、关系结构、缺失端点、自指、
  重复关系（逐副本）、每名子女至多两位父母（去重后按子女统计）、祖先环路
  （在去重后的整张图上对每条边做可达性判定，成环的每条边都报错）；
  全部问题一次性逐项返回，**不静默丢弃任何条目**，预览本身不写入任何数据。
  预览同时返回内容 **SHA-256 指纹**与当前家谱版本；确认必须原样带回，
  服务端重新计算指纹比对、并**整份重验**——指纹或版本不符（**409**）、重验失败（**400**，逐项错误）
  都零写入。成功恢复走统一 commit 入口：变更前完整家谱成为唯一撤销快照，
  新状态、新版本与快照一次落盘（成员 ID 原样保留，可直接撤销回退）。
- 成员纪念日：纪念日是成员对象上的两个字段（`birthday` / `deathday`，公历月日
  `{ month, day }` 或 `null`），随成员一同序列化落盘——因此删除成员、撤销快照与
  备份恢复都天然一并处理；旧数据文件与旧备份缺少字段时加载/恢复为 `null`（视为未登记），
  手工改坏的非法值在加载时净化为 `null`，而备份恢复走严格校验、非法即整单拒绝。
  登记/修改/清除走统一 commit 入口（版本 +1、产生撤销快照），非法月日
  （非 1–12 月、超出该月天数；2 月允许 29 日）在校验阶段整单拒绝、不产生任何写入。
  未来 30 天清单为纯函数：以浏览器提交的本地日期为第 0 天（UTC 日期运算，不受服务器时区影响），
  对每项纪念日逐年（起算年、下一年）求下一次发生日期——2 月 29 日在平年归并到 2 月 28 日，
  闰年保持 2 月 29 日——落在 `[今天, 今天+30天)` 窗口内的即入选，每项至多出现一次；
  结果按距今天数升序，同日按姓名（中文排序）、类型（生日先于忌日）、成员 ID 稳定排序。
